# X-Mirror

XMAX X2.1 驱动的轻量网页虚拟试衣间。手机与电脑通过浏览器打开，上传或录制短视频，选择服饰，生成试穿照片或短片，再前往原商品页面购买。

## 独立 toolkits

[Camera Studio](toolkits/camera-studio/README.md) 支持摄像头录制 3～10 秒短片、右侧素材与提示词、Xmax X2.1 生成、本地自动保存及历史回放。位于 `toolkits/camera-studio`，使用独立配置和输出目录，默认端口 5190。

```powershell
# 首次配置，已有文件时不要覆盖
Copy-Item toolkits/camera-studio/.env.example toolkits/camera-studio/.env
# 填写 toolkit 的 XMAX_API_KEY，按需配置代理
npm run toolkit:camera:setup
npm run toolkit:camera
```

更多说明见 [toolkits](toolkits/README.md)。素材由准备脚本下载到本地；演示图片、密钥、录像和生成结果不进入仓库。

## 本地启动

需要 Node.js 22.12+，推荐 Node.js 24。

```sh
npm ci
# 没有 .env 时，将 .env.example 复制为 .env 并填写 XMAX_API_KEY
npm run dev
```

默认地址为 `http://localhost:5180`。启动、选素材及商品解析不会调用付费试穿模型。点击“一键试穿”才创建 XMAX 会话。

当前开发目录已提供 `.env` 和参考素材；`.env`、原始参考素材及生成结果均不会进入 Git。此前 5173 端口被另一项目占用，因此本项目使用 5180。

准备本地参考素材需要系统安装 `ffmpeg`：

```sh
npm run prepare:demo
```

该脚本从 `ref_material` 和根目录 Logo 提取本地预览与参考单品。`public/demo` 不进入 Git；克隆仓库后没有原始参考素材也可以上传自己的素材使用。优化后的应用 Logo 位于 `public/brand/logo.webp`。

## 已实现的流程

默认模特使用 `ref_material/网站试衣服.mov` 的动态视频，裁剪左侧模特区域后转换为兼容浏览器的 MP4，保留原片 1.6 秒动作。人物预览和原图对比直接循环播放。有视频的模特始终以完整原片连续视频流送入试穿模型；视频自动输出同长度动态短片，照片自动输出照片。输出类型不能独立切换。小缩略图直接使用视频元素，不提取候选 JPEG。结果播放器正常速度播放一次，显示精确秒数并提供完整回放控件。

服饰按「套装 / 上衣 / 下装 / 配饰」分类。完整上下装、连衣裙、连体衣归套装，外套和衬衫等归上衣；裤子、半身裙归下装，帽子和眼镜归配饰。上传和商品链接导入使用当前选中的分类。套装与单独上衣/下装互斥，配饰可单独搭配；套装和下装要求全身素材。参考图和生成指令按类别标记完整换装或局部替换范围。内置图片分类共用 `src/demo-catalog.json`。

- 上传视频或照片；视频最长 10 秒、最大 30 MB，图片最大 10 MB。
- 人物预览和试穿输入使用原视频，保留全部动作，不提取截图作为人物输入。
- 摄像头录制，无音频，约 9.5 秒自动停止，为浏览器停止录制留出余量。
- 套装、上衣、下装、配饰四个槽位，支持替换、移除和拖入图片；可在一次生成中组合试穿。
- 读取公开商品页面的 Open Graph、Twitter 图片及 JSON-LD 商品元数据；支持直接图片链接。解析失败时保留链接，允许补传图片或显式绑定到当前单品。
- 照片收到真实远端画面后约 1 秒保存；视频按上传素材实际时长录制，最长 10 秒（容许浏览器录制停止的 0.15 秒余量）。
- 保存照片、下载短片、对比原图、跳转购买。
- 停止、取消、超时和离开页面时关闭 SDK；后端主动撤销临时密钥。

半身素材不能试套装或下装。入镜范围由用户确认，首版没有自动人体检测。已用真实 8 秒视频验证“上衣＋帽子”在同一次生成中同时替换；所选商品以逐列标记的组合参考图上传，指令要求每帧保留全部已选单品。其他组合、眼镜和不同商品的准确性仍需实测，AI 也可能改变未选中的服饰细节，不适合作为尺码或真实合身程度判断。

## API 与费用控制

使用官方 `@xmaxai/web-sdk` 的 `RealtimeModel.x2_1`。照片通过 `createLocalImageStream` 直接传入原 File；视频通过 `createExternalVideoStream` 传入标准 1080P 轨道，连续播放原始动作、保留完整内容并补边，不循环输入。视频加载后先等待首帧完成解码与绘制，再发布输入画布。服饰图通过 SDK 的存储服务上传，然后使用 `RealtimeContext` 开始生成。预览只使用 `setRemoteMediaTracksListener` 提供的原始远端视频轨道；支持 WebCodecs 时将解码画面交给 Worker 编码，编码器先预热，随后按统一时钟录制，帧时间戳不能超过原片长度；其他浏览器使用 MediaRecorder 兼容路径。远端就绪还须通过空白画面检查，保存后验证解码、首中尾画面与实际时长，页面确认播放成功后才标记完成。没有有效结果时保留原始素材并明确标记未生成。浏览器只收到受限临时密钥。

后端通过官方接口 `POST /temporary-api-key` 签发密钥，通过 `PUT /temporary-api-key/:key/inactive` 撤销。国内接口基址为 `https://cloud.xmax.22duck.cn/open/api/v1`，海外为 `https://api.xmax.ai/open/api/v1`。

实际运行上限由 `.env` 配置，并由服务端进一步限制：

- 视频生成按输入时长，最长 10 秒。签发密钥后保留最多 60 秒的启动预算，另加原片时长及 3 秒录制/传输余量；总会话仍不超过临时密钥到期前 5 秒，签发耗时也计入密钥期限。开始录制前确认剩余时间足够；不足时停止并明确提示。异常中断的短片标记为未完成，录制失败不会回退成照片。
- 单个临时密钥只允许一个连接，积分额度最多 100，最长 90 秒到期。
- 本地不限次测试：在 `.env` 设置 `XMAX_DISABLE_DAILY_LIMITS=1` 并重启，解除访客每日次数与全站每日预留预算限制；页面显示“测试次数不限”。仍记录每次会话，单次时长、积分上限和并发限制继续生效。示例配置默认关闭此开关。
- 默认每位访客每日最多五次，全站每日最多预留 1000 积分，按北京时间午夜重置；全站同时只运行一个任务。
- 在调用之前持久记录预算预留。失败和不确定的网络结果也占用预留预算，不自动退款或重试。
- `.local/sessions.json` 只保存任务标识、匿名会话摘要、时间、预留积分和撤销状态；不保存密钥或图片。

**预留积分是预算上限，不等于实际账单。** XMAX 按连接时间收费，连接初始化和等待也可能计费；实际余额、扣费及第三方素材保留时间以供应商控制台和政策为准。

`XMAX_PROXY_URL` 只配置 Node 后端 HTTP 请求。浏览器的 SDK 请求与 WebRTC 仍需要可工作的网络；只配置后端代理不保证实时媒体能连接。

## 服饰参考图

单品参考图保留原始尺寸，最长边上限 2048 像素，使用较高 JPEG 质量；多单品参考拼图高度 2048，每列 1024 像素宽。界面显示所选单品实际尺寸，对低清图给出换图建议。推荐商品正面原图最长边 1500～2000px，完整衣服、主体占比大、纹理清楚；800px 图可试用，但小图案和五金细节更容易丢失。直接放大小图无法补回原始细节。

本地内置服饰不再从 GUI 小截图放大：外套、裙子从官方原始素材提取，帽子保留原图尺寸，牛仔裤使用真实高清照片缩小至约 2048px。运行 `prepare:demo` 时仅在本地缺少牛仔裤原图时下载，网络代理沿用 `XMAX_PROXY_URL`。示例牛仔裤作者为 A Continuous Lean，来自 [Wikimedia Commons](https://commons.wikimedia.org/wiki/File:Tellason_jeans,_front.jpg)，授权 [CC BY 2.0](https://creativecommons.org/licenses/by/2.0/)，已缩小尺寸，署名也在本地使用指南中显示。素材仍不进入 Git。

## 画质、时长与响应时间（2026-11-02）

视频按方向选择标准 1920×1080 或 1080×1920，不再使用方形或 3:4 生成画布。关闭 SDK 自动降档，编码优先保留分辨率，上行最高 8Mbps，浏览器结果录制设为 8Mbps。只修改本地文件流的 `videoFormat.width/height` 无法强制高清，因为 SDK 从文件读取真实媒体尺寸、下行不自动放大；因此视频使用高清外部 Canvas 输入，并检查原生远端返回尺寸。低清原素材放大无法恢复原本缺失的细节，不对输出视频再放大冒充高清生成。照片保留原始图片输入，结果尺寸由 SDK 与模型决定。

输出类型由输入决定。录制计时从实际收到可解码画面开始，采用输入素材时长，不再使用固定 5/8 秒。RTC 轨道的时间戳可能不连续，因此通过 Canvas 与 WebCodecs 显式帧时间戳录制远端画面（不支持时使用 MediaRecorder），WebM 写入实际录制时长，可播放和定位；重复画面只保留停顿，不代表模型帧率提高；浏览器定时、编码帧边界存在约一两帧误差。生成是实时流传输，短片时间轴长度匹配输入，但网络延迟和丢帧仍可能影响动作对应，不能当作离线逐帧编辑。源视频首帧在连接预热期间保持，收到画面后才播放原片一次。

[官方实时视频说明](https://22duck.cn/docs/capabilities/realtime-video) 的约 200ms 指实时生成的端到端延迟，不等于签发密钥、上传参考图、建立 RTC 连接以及录完整短片的总时长。网页记录点击到首帧、SDK 启动分阶段耗时和 RTC 媒体延迟估计，事件为 `xmirror:first-frame`、`xmirror:metrics`；RTC 估计也不能用来证明 AI 端到端 200ms。SDK 提前加载，人物准备与服饰上传并行，结果在后台关闭连接和撤销密钥完成前即可显示；新任务仍等待清理完成。启动阶段仍受网络、代理、供应商会话创建及资源等待影响，未承诺 200ms 首帧。

## 手机访问与正式运行

同一局域网可打开 `http://电脑局域网IP:5180`，使用视频文件上传。手机摄像头录制需要 HTTPS；HTTP 页面会提供相机录制后上传的降级提示。

```sh
npm run build
npm start
```

公开部署时使用 HTTPS 反向代理，并将 `PUBLIC_ORIGIN` 配置为实际站点的完整来源，例如 `https://mirror.example.com`。该值用于访问主机和跨来源请求校验。

生产模式默认禁用本地演示素材。确需在私人测试实例展示参考素材时设置 `ENABLE_LOCAL_DEMO=1`。官方演示素材未声明开放授权，不要将它们作为可公开分发的商品或模特素材。

服务端额度日志需要持久磁盘，首版只支持一个 Node 进程。多进程部署需要共享预算和会话锁。不要为增加额度而删除当日额度日志。

## 验证

```sh
npm test
npm run test:ui
npm run build
npm run test:production
```

`test:ui` 需要先启动开发服务器和安装桌面 Chrome；它使用明确标为测试用途的 SDK 替身，不调用付费模型，验证照片与视频生命周期、摄像头、选帧、下载、取消、布局和商品流程。验证产物在 `.local/verification`。

真实验证需要已配置 API Key，会消耗额度：

```sh
npm run test:live
# 可选单独验证的类别；失败不会自动重复付费调用
node scripts/verify-live.mjs --real-api --cases=video,image
```

默认测试地址为 `http://127.0.0.1:5180`。真实输出位于 `.local/verification/live`，不会提交到 Git。

## 接口与项目结构

- `GET /api/status`：公开运行配置及当前访客剩余额度，不返回密钥或其他访客记录。
- `GET /api/catalog`：返回当前实例启用的本地参考单品。
- `POST /api/start`：通过提交标识去重、检查预算、签发临时密钥。
- `POST /api/finish`：检查会话归属并撤销临时密钥。
- `POST /api/products/resolve`：尝试解析商品页面，返回一张已下载的主图与商品名称。
- `POST /api/products/image`：校验并下载公开服饰图片。

前端位于 `src/`，模型适配位于 `src/provider.ts`，会话和费用控制位于 `server/api.mjs`，商品解析位于 `server/products.mjs`。服务端校验图片来源的 DNS 和每次重定向，拒绝内网与本机地址；直接连接会固定已校验的 IP，代理环境则仅支持内置零售与图片域名名单。

项目采用 Vite + TypeScript + 单个 Node 服务。根据提供的现有 XMAX 调用方式，使用原生浏览器页面和 SDK 比引入额外 React/Next.js 框架更直接；仍保持在一个项目内开发和部署。
