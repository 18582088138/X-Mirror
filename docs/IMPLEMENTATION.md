# 2026-11-02 媒体类型、标准 1080P 与完整回放

本节覆盖下方历史实现中的方形视频尺寸、候选截图、SDK 预览和自动循环行为。

- 图片直接传入 SDK 的 `createLocalImageStream({ file: source.file })`，生成后仅保存 JPEG；视频使用原 File 的视频 URL 连续播放和输入，不再提取五张 JPEG、不再选择截图作为人物输入或生成参考。组合参考图仅包含服饰。
- X2.1 是实时视频流模型。视频通过完整原片的视频元素连续等比绘制到标准 1920×1080（横向）或 1080×1920（纵向）上行轨道；保留所有人物内容和原片动作。没有用图片拼接冒充人物视频，也没有放大低清生成结果。SDK 的 File 视频入口会按原素材尺寸生成，并在连接预热前开始播放，不适合直接替换当前需要高清和预热后完整动作的路径。
- 视频结果检查原生远端尺寸，未达到标准 1080P 时明确失败；保存后检查解码、精确时长和首中尾画面。封面从保存的结果视频中生成，避免远端断开后丢弃已保存片段。
- SDK 预览保持在屏幕外，只用原生远端轨道显示和录制结果。每次结果只在录制后编码一次 JPEG，降低录制期间主线程负担。增加远端呈现帧率、最大帧间隔和编码跳帧统计，分别观察接收与保存环节，不以重复编码到 30fps 代表模型实际生成 30fps。
- 结果播放器不再自动循环，使用正常速度和完整进度控件，顶部直接显示两位小数秒数。原片 `网站试衣服.mov` 本身只有 1.600 秒、48 帧；原生控件把时长显示为 0:01 不代表视频只有一帧或被截短。
- 回放验证通过逐帧回调观察首尾媒体时间、整段播放所需的实际时间、缓冲和丢帧，覆盖 1.6 秒与 8 秒，比较同一文件在实际 GUI 和独立播放器里的行为。旧 8 秒文件两种播放器均约 8 秒播完；旧 Studio 文件约 17fps，低帧率在文件中已经存在，两个播放器没有缓冲或播放丢帧。实际 1080P 视频和图片 API 测试结果保存在本机 `.local/verification/live/`，不进入 Git。
- 最终真实视频验收：Studio 返回原生 1080×1920、1.600 秒、36 个可解码帧；男模返回原生 1920×1080、8.000 秒、220 个可解码帧。GUI 实际回放耗时分别约 1.645 秒、8.042 秒，均呈现到视频终点且无缓冲事件。远端呈现约 20.6fps/13.6fps，男模接收期间出现约 1.75 秒画面间隔；录制跳帧也有发生。因此当前并不宣称稳定 30fps 或逐帧离线编辑，播放器没有压缩/截短结果时间轴。图片入口已用原始 PNG 实测返回 1280×1280 JPEG。

# 2026-11-02 白屏与超长成片修复

本节覆盖下方历史实现中的首帧判断与录制计时。

- 浏览器的 loadeddata 和非零尺寸不代表暂停视频已经能绘制。实际诊断发现：原始预览有正常人物，而用于上行的暂停视频和高清轨道仍是空白。发布前先 seek 到首帧并验证像素，避免向模型持续发送白色画面；不使用封面替代人物视频。
- 远端预热期间保持视频元素渲染，等待 SDK 生成状态和连续有效画面；避免异步录制准备重入。先准备编码器，再播放原片，按有限的 RTC 延迟余量开始录制。
- 高清 WebCodecs 编码放在 Worker，使用真实编码帧完成预热。输入播放与录制使用同一时钟，所有帧时间戳严格限制在原片长度内；零时长终点帧使 WebM 的容器时长准确落到原片终点，定时器延迟不会生成额外时间。
- 保存前检查实际可解码视频、时长、首中尾非空白画面；播放器失败时保留试穿封面并明确报错，不会被结束流程覆盖为“试穿完成”。在最后帧完成采集后才清理连接和撤销凭据。
- 回归覆盖编码预热延迟 18 秒、结束回调延迟至 26 秒、远端白屏预热与持续白屏、播放器拒绝播放、摄像头清理、图片输出，以及真实播放器和下载文件的时长。
- 真实 API 验收已确认参考 Studio 视频返回 1408×1408、1.600 秒；男模白 T 恤替换为夹克，返回 1920×1080、8.000 秒并正常回放；图片输入返回 1408×1408 JPEG。实际首帧等待约 27～37 秒，未声称整次请求达到 200ms。
- 每日测试次数仍通过显式配置解除，保留单次视频长度、连接数、临时密钥和会话额度约束。

## 对初始计划的落实

根据提供的 XMAX 临时密钥配置、官方素材和已验证 SDK 接口，采用 Vite + TypeScript + 单个 Node 服务。照片模式将本地选帧作为静态视频流输入；动态模式输入本地短视频。实际生成经过 XMAX X2.1，不使用图片叠加冒充试穿。

视频输入限制为 10 秒和 30 MB。照片模式收到画面后最多再生成 3 秒，动态模式最多 8 秒。含签发和 RTC 初始化的总等待上限为 60 秒；超时若已收到画面则保留结果，没有收到则明确提示失败。

应用不在后端存储原视频、人物图片和结果图片，因此无需原计划中的图片文件保留与清理任务。XMAX 存储服务会接收服饰参考图，其保留时间未由本应用确认，界面和 README 均明确区分第三方处理规则。

连续短片的录制由浏览器完成；没有实现实时摄像头直接推流，而是先录制有限时长素材再生成。没有账户、支付、订单、3D 建模或尺码判断。
