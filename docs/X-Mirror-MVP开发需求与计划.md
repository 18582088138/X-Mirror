# XMAX X2.1 · X-Mirror 开发需求与计划

## 1. 产品目标

开发一个轻量化网页虚拟试衣间 X-Mirror，作为 XMAX X2.1 的功能模块。用户用手机或电脑浏览器打开网页，上传或录制一段本人视频，添加想试穿的衣服、裤子或配饰，生成搭配预览，满意后跳转商品页面自行下单。

首版不需要原生 App、复杂账户体系、3D 建模或自建 AI 模型。

## 2. 首版实现方式

**视频作为人物输入，试穿图片作为结果输出。**

- 用户上传或录制最多 10 秒的视频，界面建议录制 5 秒；支持全身或半身。
- 在浏览器端从视频提取少量预览帧，用户选择一张清晰画面作为人物照片。
- 后端只把选中的人物图片和服饰图片发送给试穿 API，不默认上传整段视频或逐帧调用模型。
- 用户点击“生成试穿”后得到一张搭配图片，可以更换商品再次生成。
- 全身视频可以试上衣、裤子等；半身视频主要试上衣和可见区域内的配饰。缺少腿部时提示重新上传全身素材。

这是首版的范围决策建议。若产品必须输出连续试穿视频，需要另外选择支持视频生成的服务，并重新评估费用、等待时间和人物一致性；不把这部分作为首版默认交付。

## 3. 用户流程

1. 打开 X-Mirror 网页，看到简短的拍摄说明。
2. 上传短视频，或允许摄像头后录制视频；录制在 10 秒时自动停止。
3. 查看视频预览，选择清晰的人物画面；支持重新录制或上传。
4. 粘贴商品链接，或直接上传服饰图片。
5. 将商品放入“上衣 / 下装 / 配饰”搭配槽位，每个槽位首版最多一个商品，可替换和删除。
6. 点击“生成试穿”，查看处理进度、结果或失败原因。
7. 保存结果图片，或点击搭配中对应商品的“去购买”按钮，跳转原商品链接。

首版最多三个槽位。配饰的可用类别由所选模型的实测效果决定，不承诺任意配饰均可精准试戴。

## 4. 功能需求与验收标准

### 4.1 人物视频上传与录制

- 支持移动端和桌面端浏览器；页面无需安装。
- 文件入口优先支持 MP4、MOV、WebM 等常见格式，实际以浏览器能解码的格式为准；失败时提示更换格式。
- 摄像头录制使用浏览器能力，需要 HTTPS 或本地开发环境；拒绝权限或浏览器不支持时提供上传入口。
- 最长 10 秒，上传文件上限初始设为 30 MB，均可配置。
- 超时长或超大小的视频直接拒绝并解释如何处理，首版不做复杂视频剪辑。
- 优先在本地提取约 3～5 张候选画面供用户选择；选中图片压缩、缩放后再上传。
- 提示用户保持单人、光线充足、身体无遮挡；试裤子需要腿部完整入镜。

验收：手机和电脑均可完成上传、选帧；支持录制的浏览器可完成录制；超限视频无法进入生成流程；选帧和录制不会产生模型调用费用。

### 4.2 商品输入

- 上传服饰图片是首版可靠入口，初始支持 JPG、PNG、WebP，单张不超过 10 MB。
- 图片上传后显示预览，用户手动选择上衣、下装或配饰类别。
- 商品链接由后端尝试读取公开页面中的商品标题、主图和原始链接，解析后让用户确认图片。
- 首版仅做公开页面的基础元数据解析，不绕过登录、验证码或平台访问限制；复杂平台适配后续增加。
- 链接解析失败时，保留商品链接并提示上传商品图片，流程仍然可继续。
- 后端只允许访问公开的 HTTP/HTTPS 地址，校验重定向目标，阻止访问本机、内网等地址，并限制下载大小与超时。

验收：直接上传图片能完成试穿；支持的公开链接能够展示候选主图；链接解析失败仍能通过补充图片生成并跳转原商品页面。

### 4.3 搭配与试穿生成

- 页面展示人物画面、三个搭配槽位、生成按钮和结果区域。
- 生成前校验人物图片、至少一个服饰图片、类别支持情况及人物可见区域。
- 后端通过统一的模型适配层调用一个已验证的第三方试穿服务，API Key 仅保存在服务端。
- 首版选择服务时，必须用实际图片验证上衣、下装、配饰的支持情况，并记录每次生成的费用。
- 多商品优先使用支持组合输入的服务；若只能顺序调用，需要计算总费用，并在发起前展示本次预计调用次数。
- 不支持的组合或配饰应禁用并说明原因；不能用普通图片叠加冒充完成试穿。
- 用户主动点击才生成；重复点击不会产生重复任务；失败后用户可主动重试，不做无限自动重试。
- 展示等待状态和明确错误信息；结果作为穿搭效果参考，不承诺真实尺码、合身程度或物理精度。

验收：至少一套真实素材可以端到端生成试穿结果；上衣和下装分别完成实测；首版提供的配饰类别完成实测；如供应商无法满足，记录缺口并调整范围后才能宣称功能完成。

### 4.4 结果与购买

- 展示生成图片，支持下载，以及返回修改搭配。
- 展示搭配商品与原始链接，用户点击后在新页面打开商品页面。
- 只有图片、没有链接的商品可以试穿，但不显示购买按钮。
- 不接入支付、购物车、订单同步或自动下单。

验收：生成结果可以保存；购买入口跳转正确商品页面；缺少链接的商品不会出现无效购买入口。

### 4.5 成本与数据处理

- 视频时长限制主要控制上传与处理量；模型费用通过选帧后只生成一次、限制分辨率和调用次数控制。
- 设置单次任务调用上限、每日任务额度和供应商费用预算；预算或额度用尽时后端拒绝新增任务。
- 首版默认不持久保存原视频，原视频在浏览器本地处理。
- 上传的人物图片、服饰图片和生成结果只作临时处理；初始保留时间设为 24 小时，后台清理。第三方保存策略需随供应商确认并在页面说明。
- 生成前简短说明人物图片会发送至第三方服务，并要求用户确认素材已获授权。
- 服务端日志不记录图片内容、密钥或可直接访问私人图片的临时地址。

验收：密钥不进入前端产物；后端拒绝超额度任务；同一次提交不重复计费；临时文件按配置清理。

## 5. 建议技术方案

采用单个 Next.js + TypeScript 项目，同时承载响应式页面和后端接口，使用简单 CSS 或项目现有样式方案。首版不引入微服务。

- 视频上传、录制和选帧：浏览器文件 API、MediaRecorder、video 和 canvas。
- 试穿：一个第三方服务，通过 `TryOnProvider` 接口封装，先验证能力再确定供应商。
- 任务状态：创建任务后返回任务 ID，前端轮询状态；优先使用供应商异步任务机制。不要让浏览器长时间等待一个同步请求。
- 临时素材：按部署环境选临时文件或对象存储，生成难以猜测的标识，禁止公开目录列表。
- 部署：选择支持所需运行时间和临时素材处理的 HTTPS Node.js 环境；公开使用时，任务状态、额度和去重信息放入轻量持久存储。
- 无登录首版可采用受限访客会话与服务端限流；公网试运行设置总预算硬上限。

如果后续发现 XMAX X2.1 已有可复用的前后端与登录能力，优先融入现有项目，不另建重复基础设施。当前目录为空，尚无可确认的现有技术栈。

建议接口：

- `POST /api/products/resolve`：解析公开商品链接，返回标题、图片候选、原链接或可理解的失败原因。
- `POST /api/try-on`：校验人物与服饰输入、预算和去重信息，创建试穿任务。
- `GET /api/try-on/:id`：返回当前访客有权访问的任务状态和结果。

任务最少包含：任务 ID、所属会话、人物图片、服饰条目、状态、供应商任务 ID、结果地址、错误原因和到期时间。服饰条目包含类别、图片及可选商品标题和链接。

## 6. 开发计划

### 阶段一：验证试穿服务

1. 确认一个候选服务的接口、价格、输入限制、输出格式、耗时与素材保存规则。
2. 使用获授权素材分别测试半身上衣、全身上衣加裤子、至少一种配饰。
3. 确定首版支持的组合、分辨率、单次调用次数和预算上限。

交付：可运行的最小 API 验证和能力记录。未验证服务前，不把模拟结果作为真实试穿交付。

### 阶段二：完成网页输入流程

1. 实现响应式单页布局。
2. 完成视频上传、摄像头录制、10 秒自动停止、文件校验和本地选帧。
3. 完成服饰图片上传、搭配槽位和商品链接解析失败时的补图流程。

交付：手机与电脑均可准备完整试穿输入，尚未配置模型时明确提示。

### 阶段三：接通试穿与购买闭环

1. 实现服务端模型适配、任务创建和状态查询。
2. 加入生成前校验、去重、限流、预算控制和失败提示。
3. 展示真实结果，支持下载、修改搭配以及跳转商品页面。

交付：从本人短视频到真实试穿图片再到商品购买页面的完整流程。

### 阶段四：验证并部署

1. 在 iOS Safari、Android Chrome 和桌面 Chrome 上验证主要流程；录制不兼容时验证上传降级入口。
2. 验证超时长、文件超限、权限拒绝、链接解析失败、供应商失败、重复提交和额度用尽等场景。
3. 确认 HTTPS、密钥配置、素材清理、任务访问隔离与部署运行时限制。
4. 记录支持的商品类别、已知效果局限和真实调用费用。

交付：可访问的网页地址、环境变量示例、启动说明和简短验收记录。

## 7. 暂缓功能

- 连续视频试穿与实时摄像头换装。
- 3D 人体、精确尺码推荐和布料物理模拟。
- 所有电商平台商品链接的自动解析。
- 任意类别配饰、多件同类衣物及复杂叠穿。
- 账户体系、云端衣橱、社交分享、站内支付和订单管理。

## 8. 可直接交给开发 Agent 的指令

请开发 XMAX X2.1 的轻量化网页虚拟试衣间 X-Mirror。手机和电脑使用浏览器即可。用户可以上传或通过摄像头录制本人全身或半身短视频，建议 5 秒、最长 10 秒，在浏览器本地选取清晰帧；通过商品链接或服饰图片添加上衣、下装和经实测支持的配饰，点击生成试穿图片，保存结果并跳转商品链接购买。

先验证真实试穿 API 的能力、费用和数据处理规则，再实现响应式单页流程与服务端集成。优先用一个 Next.js + TypeScript 项目；如已有 XMAX 技术栈则复用。API Key 只放服务端，限制任务调用次数、访客额度与总预算。商品链接解析失败时允许上传图片补充。提供清楚的等待、失败、重试和不支持类别提示。半身素材不应尝试缺少可见区域的下装试穿。

首版以视频输入、图片输出交付，不实现连续视频生成、原生 App、3D 建模或站内支付。模拟数据只能用于界面开发，需明确标注；最终验收必须包含真实模型生成结果。按本文四个阶段执行，每阶段交付可运行结果并记录验证情况。缺少供应商凭据时完成无需凭据的界面和服务端适配，同时明确记录真实集成尚未验收。
